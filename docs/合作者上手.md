# 合作者上手（約 10 分鐘讀完）

這份文件給**負責擴充校園資料**的人：新增大樓、放熱點、加樓層／節點、做跨棟連線。  
**不必改程式**；維護者負責功能與 bug。

---

## 誰做什麼

| 角色 | 負責 | 通常會動到的檔案 |
|------|------|------------------|
| **合作者（你）** | 平面圖、全景、節點、連線、大樓定義 | `data/buildings.json`、`data/nav-settings.json`、`data/nodes/*.json`、本機 `images/` |
| **程式維護者** | 功能、設定頁、驗證腳本、導航邏輯 | `src/`、`scripts/`、`*.html`、`style.css` |

目前建議由合作者優先做：

1. **補齊已登記大樓的節點**（例如缺少 `m_1`、`cc_1`、`ee_7` 時，進該樓層補點）
2. **棟與棟／校門口的室外連線**（多半在校園總圖 `campus.json`，必要時跨 scope 連到各棟入口）

用完請 **commit 資料檔並開 PR**（或依團隊流程交給維護者合併）。  
`images/` **不進 Git**，圖檔請用雲端／隨身碟與維護者同步。

---

## 第一次環境（約 5 分鐘）

1. 向維護者取得：完整 `images/`、本機設定（或自己從範例複製）
2. 雙擊 `setup-env.bat`（第一次），之後用 `start-server.bat`
3. 瀏覽器開 `http://localhost:5173/` → 管理登入 → 進入導覽頁
4. **一定要用 start-server**（同時開 API），否則編輯結果寫不回 `data/`

管理員密碼：見 `config/admin.local.json`（**不要提交**）。建議執行  
`node scripts/hash-admin-password.cjs "密碼"` 產生 `passwordHash` 後貼上；或由維護者提供已設好的本機設定。  
未設密碼時無法登入（不會再用範例 `changeme`）。

開發時 Vite（5173）可能仍看得到設定頁畫面，但**寫入資料必須已登入**。

## 資料檔對照（只要記這三類）

| 檔案 | 存什麼 |
|------|--------|
| `data/buildings.json` | 大樓有哪些、名稱、每層平面圖路徑 |
| `data/nav-settings.json` → `campusBuildings` | 校園地圖上的藍色入口按鈕位置／開關／顯示名稱 |
| `data/nodes/{大樓}_{樓層}.json` | 該樓層的環景節點與連線；校園總圖是 `data/nodes/campus.json` |

例子：`S 棟 1F` → `data/nodes/s_1.json`；`EE 棟 3F` → `data/nodes/ee_3.json`。

## 流程 A：新增大樓（從零到能進去）

1. 準備圖檔（路徑建議）：
   - 平面圖：`images/{大寫代碼}/floorplan-{小寫}-{樓層}.jpg`  
     例：`images/M/floorplan-m-1F.jpg`
   - 全景：`images/{大寫代碼}/{樓層}/xxx.jpg`  
     例：`images/M/1F/m1001.jpg`
2. 導覽頁 → **自製平面圖**（不要用衛星示意）→ 管理員 **編輯模式**
3. 「＋ 新增大樓」→ 填名稱、代碼（如 `m`）、首層標籤與平面圖路徑 → 在地圖上**點一下**放熱點
4. 點藍色按鈕進入大樓 → 編輯模式 → 點平面圖加節點、設連線與距離
5. 多樓層：到 **設定頁 →「校園大樓」**該大樓卡片 →「＋ 新增樓層」→ 改平面圖路徑 → 再進該層補節點

完成後可進訪客頁／搜尋，確認能找到新節點。

---

## 流程 B：補齊既有大樓的樓層節點

適用：`buildings.json` 已有樓層，但地圖進去是空的，或驗證腳本警告缺少節點檔。

1. `npm run validate:buildings`（看還缺哪些檔）
2. 設定頁「校園大樓」確認該層平面圖路徑正確，圖檔已放在 `images/`
3. 導覽頁進入該棟該層 → 編輯模式 → 依走道放置節點、雙向連線
4. 教室／地點：編輯模式「＋ 目的地」點平面圖（綠色標記），可拖到門位；進環景可補朝向
5. 樓梯／電梯：連到其他樓層對應節點（跨樓層連線）
6. 再跑一次驗證，確認該層警告消失

---

## 流程 C：跨棟／校門口連線（室外路徑）

目標：訪客從「校門口」或 A 棟能走到 B 棟，路徑算得出來。

1. 回到**校園總圖**（自製平面圖）
2. 編輯模式：在室外走道、廣場、大門等處加節點（寫入 `data/nodes/campus.json`）
3. 把室外節點**連成網**（雙向、填距離）
4. **接上各棟入口**：從室外節點連到該棟 1F（或實際入口層）的入口節點  
   （編輯連線時可選其他樓層／棟的節點）
5. 訪客頁試一條：例如「校門口 → EE 棟某教室」「P 棟 → EE 棟」

建議優先補：校門口 ↔ 主要棟入口、已有資料的棟與棟之間（如 S／P／EE）。

## 常用操作速查

| 想做的事 | 怎麼做 |
|----------|--------|
| 移動大樓按鈕 | 編輯模式 → 拖曳藍色按鈕 |
| 刪除大樓 | 編輯模式右鍵藍色按鈕，或設定頁「校園大樓」→「刪除此大樓」（可再選是否一併刪節點檔） |
| 暫時關閉某棟入口 | 設定頁「校園大樓」關閉該棟熱點（地圖上變灰） |
| 改大樓顯示名稱 | 設定頁「校園大樓」→「大樓名稱」 |
| 改地圖按鈕文字 | 設定頁「校園大樓」→「按鈕顯示名稱」（可留空） |
| 刪節點 | 編輯模式右鍵紅點 |
| 加目的地標記 | 編輯模式 →「＋ 目的地」→ 點平面圖空白處（綠色標記，綁定最近紅點的環景）。可拖到教室位置；進環景可補朝向 |
| 刪目的地 | 編輯模式右鍵綠色標記 |

## 提交前檢查

管理員登入後可到 **設定頁 → 分頁「資料檢查」→「檢查大樓與節點資料」**，不必開終端機。

也可在專案根目錄執行：

```bash
npm run validate:buildings
node scripts/validate-nodes.cjs
node scripts/validate-nodes.cjs --reverse
```

- `validate:buildings`：大樓定義、熱點、節點檔是否對得上  
- `validate-nodes`：連線是否指向不存在的節點；目的地缺名稱或平面圖座標會列警告  
- `--reverse`：同樓層是否缺回頭路（警告，可依需要補）

**建議 commit 的檔案：**

- `data/buildings.json`
- `data/nav-settings.json`（若動過熱點／訪客設定）
- `data/nodes/*.json`

**不要 commit：**

- `config/*.local.json`
- `images/`（另傳圖檔）
- `node_modules/`、`dist/`

Commit 訊息請用繁中、簡短明確（例：`data: 補齊 M 棟 1F 節點與校門口連線`）。

## 卡住時

| 現象 | 可能原因 |
|------|----------|
| 畫面寫「找不到平面圖：images/…」 | 該層平面圖還沒放到對應路徑 |
| 環景寫「找不到環景圖：images/…」 | 全景 JPG 路徑或檔名不對 |
| 編輯後重新整理就不見 | 沒用 `start-server.bat`，或未登入管理員 |
| 找不到新大樓節點 | 節點檔沒寫入／沒進對的樓層；跑 `validate:buildings` |
| 藍鈕拖不動／右鍵沒反應 | 未開編輯模式，或目前是衛星示意（請切自製平面圖） |
| 路徑算不出來 | 室外與棟入口沒連上，或只做了單向連線 |

還是不行：把操作步驟、樓層名稱、截圖或 Console 錯誤給程式維護者。
